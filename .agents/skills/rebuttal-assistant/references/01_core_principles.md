# 01 — Core Principles

## 1. 态度：沟通，不是对抗

- 真诚、礼貌、专业。
- 通常先感谢审稿人提出的问题，但避免每句话机械重复同一种感谢。
- 把评审意见视为澄清和改进机会，而不是辩论。
- 即使审稿意见不准确，也不讽刺、不指责、不情绪化。

## 2. 立场：诚恳，但不顺从负面判断

- 不直接接受未经证明的负面结论。
- 区分“方法本身存在问题”与“论文没有把方法讲清楚”。
- 如果原稿已有证据，应主动指出并解释。
- 如果审稿人的判断有部分合理之处，可以承认具体部分，但不要扩大为对整篇工作的否定。
- 不为表现诚恳而反复强调论文没有做到什么。

示例逻辑：
- 可以承认：“The presentation of this component could be clearer.”
- 不应因此写成：“We agree that the proposed method is ineffective.”
- 如果审稿人质疑 novelty，应解释真实差异，而不是直接承认“缺乏创新”。

## 3. 证据：观点必须落到事实

- 用论文中的实验、公式、表格、图、章节和文献支持观点。
- 先给结论，再给证据。
- 审稿人问数量、原因或实验结论时，直接给出明确答案。
- 不让审稿人自己翻论文找答案。
- 证据不足时明确标记，不得编造或夸大。

## 4. 局限：承认并界定边界

承认局限时，应回答：
1. 局限具体是什么？
2. 影响哪些场景或结论？
3. 是否影响论文的核心主张？
4. 现有证据能支持到什么程度？
5. 是否有可行的后续改进？

避免空泛的“We acknowledge this limitation”。应尽量给出边界和影响说明。

## 5. 行动：具体、可信、可执行

- 说明做了什么、将做什么、修改在哪里。
- 不用“We will improve the writing”作为唯一回应。
- 可具体写出重写哪一段、增加哪张图、补充哪张表或澄清哪个公式。
- 只有会议规则允许且作者能够完成时才作未来承诺。
- 已经完成的工作应使用完成时或直接报告结果，不要写成未来计划。

## 6. 结构：每条回复有明确结论

推荐逻辑：
1. 直接回答。
2. 证据。
3. 必要解释或限定。
4. 具体行动及位置。
5. 总结性结论。

不是每条回复都要写成五段，但必须让读者清楚知道“答案是什么”和“证据说明什么”。

## 7. 表达：自然、清楚、克制

- 使用自己能准确解释的术语。
- 避免过度复杂句、堆砌学术词汇。
- 减少不必要的括号和分号。
- 不用空泛形容词代替论证。
- 让 Area Chair 和 Reviewer 能快速看到核心答案。

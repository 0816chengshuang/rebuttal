# 07 — Workflow and Output Formats

## 1. 推荐工作顺序

1. 确认会议/期刊、届次、Track、投稿类型和评审阶段。
2. 调研官方 Rebuttal / Author Response 模板、投稿系统字段和格式规则，形成 Submission Format Brief。
3. 阅读论文全文及相关实验材料。
4. 解析 Reviewer 评分与意见。
5. 建立双维度问题分类。
6. 识别低分审稿人和关键拒稿理由。
7. 建立问题—证据映射。
8. 决定补实验、澄清、解释、承认局限或修改表达。
9. 写中文逻辑稿。
10. 写英文回复。
11. 压缩并检查字符。
12. 检查格式与提交规则。

## 5. Default final response structure

```text
[Optional] Common Response

Response to Reviewer R1

Q1: [Concise concern]

A1: [Direct answer, evidence, clarification, action, conclusion]

Q2: ...

A2: ...

Response to Reviewer R2

Q1: ...
A1: ...
```

## 6. Common Response rules

适用于多个审稿人提出相同或高度重叠的问题。
- 统一回答共性事实、实验设置或方法解释。
- 不要为了节省字符而忽略个别审稿人的独特问题。
- Reviewer-specific response 可简短引用 Common Response，但要确保问题被明确回应。
- 如果会议格式不支持 Common Response，应改用其允许的组织方式。

## 7. Deliverable modes

根据用户要求选择输出，不必每次全部输出：

- **Review analysis**：逐条翻译、分类、识别核心关注点。
- **Strategy plan**：回复优先级、证据需求、补实验建议。
- **Chinese logic draft**：完整中文论证稿。
- **English rebuttal**：英文 Q/A 终稿。
- **Revision**：修改现有回复并保留原意。
- **Compression**：在字符限制内压缩。
- **Audit**：检查证据、语气、逻辑、规则和字符。
- **Meeting report**：汇总评分、审稿意见、风险和回复方案。


## 7. Submission-ready output

最终交付必须匹配实际投稿入口，而不是默认生成一份通用 Markdown 文档：

- 若系统按 Reviewer 分栏：逐栏输出可直接粘贴的回复。
- 若系统提供单一文本框：输出一份完整、顺序正确的合并回复。
- 若系统提供 Common Response 和 Reviewer-specific 字段：分别生成对应内容。
- 若存在给 Area Chair / Editor 的保密字段：单独起草并明确标记为 confidential，不得混入公开回复。
- 若期刊要求 point-by-point response letter：生成正式回复信，并按要求配套说明修订稿、标记修改或编辑信。
- 在每个字段旁标注字符数/字数及计数口径；若官方计数规则未知，明确说明估算口径。
- 不添加系统不允许的外链、附件、表格、公式或身份信息。

在交付前，再次对照 Submission Format Brief 检查字段、顺序、长度和格式。
